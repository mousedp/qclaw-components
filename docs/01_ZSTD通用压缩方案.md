# 项目文档 01：ZSTD 全域压缩方案

> 项目文档库 — 记录系统设计、方案选型、实现过程、技术结论
> 创建：2026-05-18  |  维护：皮皮鲁（微信端）

---

## 一、背景与目标

### 要解决的问题
工作区内存在大量文件（.py 组件、.pkl 数据、.md 记忆文件），占用磁盘空间且加载缓慢。需要一套**统一的、无损的、低依赖的压缩方案**，覆盖所有文件类型。

### 核心约束
1. **不修改源文件格式** — 记忆系统、规则文件是全局自动生成的，不能动原文
2. **不引入外部索引依赖** — 索引一坏系统崩，风险不可接受
3. **零新增压缩工具** — 能一套 ZSTD 搞定就不上第二套
4. **向后兼容** — 已有压缩文件（.py/.pkl）不能受影响
5. **无损** — 压缩解压后字节必须完全一致
6. **零云零API** — 全程本地运行

## 二、方案选型过程

### 方案A：专用 .md 压缩工具（已淘汰 ❌）

候选工具：
| 工具 | Star | 结果 |
|------|:----:|:----:|
| remark | 17k+ | 压 SOUL.md 只到 99%（几乎没压） |
| markdown-it | 15k+ | 未测试（同类工具，预计效果相似） |
| compact.md | 2.5k+ | npm 404 无法安装 |
| md-minify | 1k+ | 未测试（轻量，但效果预计类似 remark） |

**淘汰原因**：文本级压缩对已精炼的 .md 文件收益为 0。且多一个工具多一套维护。

### 方案B：结构索引 + ZSTD（豆包方案，已淘汰 ❌）

将 .md 文件解析为结构化块（标题/代码块/列表），构建索引后 ZSTD 压缩。

**实际测试**：
```
纯ZSTD压SOUL.md:  43%
结构索引+ZSTD:    44%
```

**淘汰原因**：压缩率基本一样，但多了一层索引依赖。用户决定：「多一层依赖多一层风险，索引一坏整个系统崩，不接受。」

### 方案C：ZSTD 全局字典 + 帧标记（最终选中 ✅）

ZSTD 内置功能，不修改源文件，不引入外部索引。

**选型理由**：
1. 不动源文件 — 纯字节级压缩，不改 MD/PY 原文
2. 无索引依赖 — 文件类型标识内嵌在压缩流（Skippable Frame）中
3. ZSTD 成熟稳定 — Meta 维护的开源老牌工具
4. 字典降级安全 — 字典坏了用原生 ZSTD 降级解压
5. 改造成本极低 — 90% 参数配置，几行调用代码

## 三、最终方案设计

### 架构总览

```
               ╔════════════════════════════════╗
               ║     ZSTD 全域压缩系统          ║
               ╠════════════════════════════════╣
               ║  zst_透明层.py  (核心引擎)      ║
               ║  zst_压缩器.py  (批量管理)      ║
               ║  zst_import.py  (import hook)  ║
               ╚════════════════════════════════╝
                        │
      ┌─────────────────┼─────────────────┐
      ▼                 ▼                 ▼
  ┌──────┐        ┌──────────┐       ┌──────┐
  │ .py  │        │  .md     │       │ .pkl │
  ├──────┤        ├──────────┤       ├──────┤
  │纯ZSTD│        │字典+ZSTD │       │纯ZSTD│
  │无标记│        │+帧标记   │       │无标记│
  └──────┘        └──────────┘       └──────┘
   ↓ import hook   ↓ zst_read_md()   ↓ zst_pickle_load()
   透明解压         透明读取          透明加载
```

### 文件格式规范

**.py 文件（v1 标准）：**
```
[ZSTD Frame]           ← 纯 ZSTD 压缩，无帧标记
```
兼容原始 ZSTD 规范，import hook 识别魔数 `0x28B52FFD` 后透明解压。

**.md 文件（v2 新标准）：**
```
[Skippable Frame]      ← ZSTD 协议原生，magic 0x184D2A50
  ├── 文件类型标识      ← "MD\0\0" (4字节)
  └── 帧大小            ← 标准 ZSTD Skippable Frame 格式
[ZSTD Frame]           ← 使用 md.zdict 字典压缩的内容
```
- Skippable Frame 是 ZSTD 协议标准部分，任何 ZSTD 解压器都会自动跳过
- 字典存储在 `中枢数据/md.zdict`（64KB，训练生成）
- 没有字典时自动降级为纯 ZSTD 压缩

**.pkl 文件（v1 标准）：**
```
[ZSTD Frame]           ← 纯 ZSTD 压缩，无帧标记
```

### 压缩字典

| 字典 | 路径 | 大小 | 文件类型 | 作用 |
|:----|:----|:----:|:--------:|:----:|
| md.zdict | `中枢数据/md.zdict` | 64KB | .md | 提升 .md 同类文件压缩率 15-98% |

字典训练样本：工作区 50 个代表性 .md 文件（SOUL/AGENTS/MEMORY/记忆日志等）

## 六、使用说明

### 压缩所有文件
```bash
python zst_压缩器.py --all
```
扫描工作区所有 .py 和 .md 文件，按各自策略压缩。

### 仅压缩 .md 文件
```bash
python zst_压缩器.py --all
```
（--all 同时处理 .py 和 .md，当前无单独的 --md-only 参数）

### 透明读取压缩文件
```python
from zst_透明层 import *

# 读 .md.zst（自动识别帧标记+字典）
内容 = zst_read_md('中枢数据/SOUL.md.zst')

# 读 .zst（兼容新旧格式）
数据 = zst_read('中枢数据/向量记忆.pkl')

# 检测文件信息
类型 = 检测文件类型('中枢数据/SOUL.md.zst')  # 返回 'MD'
是zst = 是zst('中枢数据/向量记忆.pkl')         # 返回 True
```

### 还原
```bash
# 从备份还原所有文件
python zst_压缩器.py --restore

# 解压所有 ZSTD 为明文（独立模式）
python zst_压缩器.py --standalone
```

### import hook（.py 文件自动解压）
```python
# 在 .pth 或 sitecustomize.py 中配置后自动生效
import zst_import  # 激活 import hook
import 简芯_v1     # 自动解压 ZSTD 压缩的 .py 文件
```
已通过 `zst_import.pth` 永久安装在 user site-packages 中。

## 七、设计决策为什么

### 为什么 .py 不用字典？
- .py 文件已经达到 67% 压缩率
- import hook 需要保持极简，不加字典依赖
- .py 文件格式差异大（函数、类、注释），字典增益有限

### 为什么 .md 用字典？
- .md 文件格式高度相似（标题/列表/代码块/中文）
- 同类型内容字典增益显著（15-98%）
- 字典损坏仍可降级，风险可控

### 为什么帧标记用 Skippable Frame 而不是自定义头？
- ZSTD 协议原生支持，任何 ZSTD 解压器自动跳过
- 不破坏 ZSTD 格式兼容性
- 不需要魔改 ZSTD 源码

### 为什么保留原始 .md 文件明文？
- 系统工具（read/memory_search）读取原始文件
- 压缩副本（.md.zst）供 Python 组件使用
- 互不影响，各取所需
