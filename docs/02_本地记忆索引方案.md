## 一、为什么要把索引从云端拉回来

### 背景
系统运行初期，记忆索引（由 6 维神经网络组件生成的搜索数据）存放在**天翼云**上。原因是部署阶段 6 维系统不完善，本地性能不足，需要云端的算力进行索引构建和检索。

### 拉回原因
| 原因 | 说明 |
|:----|:------|
| **响应速度** | 云端查询有网络延迟（50-200ms），本机 0 延迟 |
| **本地压缩已成熟** | ZSTD 全域压缩方案落地后，原 250MB 索引可压到 1.3MB（99.5%） |
| **天翼云定位是工作台** | 临时测试平台，不是生产环境，不应放永久性数据 |
| **成本控制** | 云端按量计费，本地零成本 |
| **稳定可控** | 本地服务自己管，不依赖外网/云平台可用性 |

### 实际发现
原云端索引文件（`云端_mem_index.pkl`，250MB）已损坏不可恢复（pickle 帧只有 16MB 有效数据，其余 234MB 是垃圾）。所幸本地 HTTP 服务器（简芯HTTP守护）已有完整搜索能力，**不需要这个文件也能正常工作**。

## 二、索引了哪些内容

HTTP 服务器（简芯HTTP守护）目前索引的内容来自**6 维神经网络记忆组件**：

### 索引清单

| 序号 | 索引类型 | 数据来源 | 文件位置 | 文件大小（压缩后） | 说明 |
|:---:|:--------|:--------|:--------|:----------------:|:------|
| 1 | **向量记忆**（TF-IDF） | 用户对话、系统消息 | `中枢数据/向量记忆.pkl` | ~1KB | 全文搜索基础，关键词权重检索 |
| 2 | **知识图谱**（关系网络） | 知识点关联、因果关系 | `中枢数据/知识图谱.pkl` | ~1KB | 概念之间的关联关系 |
| 3 | **蒸馏知识**（精华提取） | 重复知识的压缩摘要 | `中枢数据/蒸馏知识.pkl` | ~1KB | 高频信息的精简版 |
| 4 | **锚点记忆**（关键节点） | 重要决策、里程碑事件 | `中枢数据/锚点记忆.pkl` | ~1KB | 系统关键节点快速定位 |
| 5 | **长上下文**（时序窗口） | 最近对话的片段 | `中枢数据/长上下文.pkl` | ~1KB | 短期上下文保留 |
| 6 | **简芯权重**（神经网络参数） | TF-IDF + 线性模型训练结果 | `中枢数据/简芯权重.safetensors` | 87KB | 模型权重，文本→向量映射 |
| 7 | **记忆卡**（持久化配置） | 用户偏好、系统设置 | `中枢数据/记忆卡.json` | ~1KB | 零散配置项 |
| 8 | **md.zdict**（ZSTD字典） | 工作区 .md 文件训练 | `中枢数据/md.zdict` | 64KB | .md 文件专用压缩字典 |

### 检索能力

| 端点 | 功能 | 输入 | 输出 |
|:----|:----|:----|:----|
| `/search?q=关键词` | 全文搜索 | 查询词 | 相关记忆项（含评分） |
| `/predict?t=文本` | 分类预测 | 文本 | 所属类别 + 置信度 |
| `/feed` | 投喂学习 | 文本+来源 | 训练确认 |
| `/status` | 状态查询 | 无 | 已学条数、分类数 |

## 三、新增索引类型流程

当需要添加新的记忆维度（如未来第 7 维"时间商"）时：

1. **创建数据文件** — 在 `中枢数据/` 下创建新的 `.pkl` 文件
2. **注册组件** — 更新 `slot_组件.py` 注册新组件到简芯
3. **添加端点** — 更新 `简芯HTTP守护.py` 添加新端点（如需）
4. **更新本文档** — 将新索引类型加入上方的清单表

## 四、常见故障处理

### 索引文件损坏
```
场景：pickle 加载失败（EOFError）
原因：写入过程中断
解决：从 _zst备份/ 还原
预防：zst_压缩器.py --all 会自动备份
```

### 搜索无结果
```
场景：/search 返回空列表
原因1：神经网络未训练（刚重启，0条）
       → 投喂一些数据，等待训练完成
原因2：搜索词与索引内容不匹配
       → 换关键词重试
原因3：索引文件损坏
       → 从 _zst备份/ 还原
```
