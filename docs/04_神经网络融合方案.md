## 一、背景

### 融合前架构

神经网络系统原本由多个独立组件构成，各自有自己的数据流和生命周期：

```
slot_向量.py    → TF-IDF 向量化核心（独立文件，ZSTD压缩）
slot_海马体.py   → 短期记忆管理 + 时间衰减
slot_锚点.py    → 重要记忆标记系统
slot_蒸馏.py    → 知识蒸馏过滤
slot_上下文.py   → 对话长上下文窗口
slot_图谱.py    → 知识图谱网络（U盘插件）
slot_组件.py    → 插槽注册管理器
简芯_v1.py      → 神经网络核心 + Dedup自加载
简芯HTTP守护.py  → HTTP 服务器
```

### 痛点

| 问题 | 表现 | 后果 |
|:----|:-----|:-----|
| 数据孤岛 | 投喂只喂了神经网络，其他组件各自为政 | 搜索不能协同利用所有组件 |
| 调用链长 | 每次搜索要分别调 N 个组件再合并结果 | 性能差，容易遗漏 |
| 无协同过滤 | 蒸馏只看文本重复，锚点只看关键词 | 无法做组合决策 |
| 升级困难 | 想加新功能要改 N 个组件 | 不敢改、改不动 |

### 决策过程

叶子提出关键理念：**蒸馏是"超级过滤器"，放在神经网络输入层，而不是做预处理。**

```
原始信息 → [蒸馏过滤器] → 锚点检查 → 海马体 → 上下文
                ↑
         神经网络的输入层
```

蒸馏作为输入层的价值 vs 预处理：

| 维度 | 预处理（旧理解） | 输入层（叶子理念） |
|:----|:---------------|:-----------------|
| 位置 | 在神经网络外面 | 在神经网络里面 |
| 判断依据 | 静态规则（长度/关键词） | 已学的 TF-IDF 模型（语义相似度） |
| 自适应 | 不能 | 可随训练调整阈值 |
| 反馈循环 | 无 | 学得越多，过滤越精准 |

同样，**长上下文长期记忆融进神经网络**的最大价值是搜索增强——搜"那个方案"能根据最近3轮对话自动扩展为"刚才讨论的COS云端存储那个方案"。

### 最终决策

| 组件 | 叶子判断 | 理由 |
|:----|:---------|:-----|
| 蒸馏（理念） | ✅ 融 | 超级过滤器，放在神经网络输入层 |
| 蒸馏（结果） | ✅ 融 | 过滤后的压缩数据直接投喂 |
| 海马体 | ✅ 融 | 时间衰减 + 共享投喂 |
| 锚点 | ✅ 融 | 自动检测 + 搜索加权 |
| 长上下文 | ✅ 融 | 搜索增强，让搜索变聪明 |
| 知识图谱 | ❌ 不融 | 数据本质不同（图 vs 向量），保持U盘插件独立 |
| 长上下文压缩（TTTD） | ❌ 跳过 | 未实现，暂时不管 |

**叶子权衡：** "融进去神经网络可以跳跃式升级，但以后单维度改造麻烦。将来麻烦也没办法，现在必须跨越式升级。"

## 二、融合架构

### 投喂流程

```
投喂(文本)
  │
  ├─❶ 蒸馏过滤器
  │    Jaccard 相似度检查（跟 self.条目 中所有已学内容比较）
  │    字符集重叠率 > 0.85 → 判定为重复 → 拦截不学
  │    → 返回 {'已过滤': True}
  │
  ├─❷ 神经网络核心
  │    TF-IDF 向量化 + MLP 训练
  │    自动分类到已有/新建来源类别
  │    → 返回 {'已学习': True, '总计数': N}
  │
  ├─❸ 海马体同步
  │    投喂后自动调用 海马体.投喂(文本)
  │    维持短期记忆窗口
  │
  ├─❹ 长上下文同步
  │    投喂后自动调用 上下文.喂(文本)
  │    维持对话窗口
  │
  └─❺ 锚点自动标记
      匹配关键词：关键/重要/记住/方案/核心/部署/策略/架构/规则
      符合 → 自动钉锚点
```

### 搜索流程

```
搜索(关键词)
  │
  ├─❶ 上下文增强
  │    取最近3轮上下文 → 合并到查询词
  │    q = 关键词 + ' ' + ''.join(上下文)[:100]
  │
  ├─❷ TF-IDF 检索
  │    TextVectorizer.search(q, 条目, top_k * 2)
  │    点积相似度排序
  │
  ├─❸ 时间衰减
  │    24小时半衰期指数衰减：
  │    score = score × (0.5 + 0.5 × e^(-Δt/86400))
  │
  ├─❹ 锚点加权
  │    被锚点标记的记忆 ×1.2
  │    Jaccard > 0.7 即判定为关联锚点
  │
  ├─❺ 知识图谱合并（U盘可选）
  │    独立调用 图谱.搜(关键词)
  │    结果并入排序列表
  │
  └─❻ 去重排序
      合并结果 → 同文本保留高分 → 取 Top-K
      → 返回 [{'text': ..., 'score': ...}, ...]
```

### 核心类设计

| 类 | 职责 | 关键方法 |
|:---|:-----|:---------|
| `TextVectorizer` | TF-IDF 向量化 + 语义搜索 | `tokenize()`, `fit()`, `transform()`, `search()` |
| `简芯` | MLP 神经网络核心 | `forward()`, `投喂()`, `预测()`, `保存()`, `加载()` |
| `简芯守护` | 融合守护者 | `投喂()`, `搜索()`, `预测()`, `扫描记忆()`, `持久化()` |

### 文件结构

```
简芯_v2.py               → 核心文件（14.5KB，~310行）：神经网络 + 全部融合组件 + HTTP
简芯HTTP守护.py           → 改用 from 简芯_v2 import 简芯守护
slot_海马体.py / 锚点.py   → 保留（作为依赖模块，简芯_v2 内部 import）
slot_蒸馏.py / 上下文.py   → 保留
slot_向量.py / 组件.py    → 保留
slot_图谱.py              → 保留（U盘插件，不融）
_pre_merge_backup/        → 10个原始文件备份
```

## 三、实施过程

### 3.1 备份（6次失败→最终成功）

**核心问题：ZSTD压缩文件解码。**
- `简芯_v1.py` 和所有 `slot_*.py` 都是 ZSTD 压缩格式（magic header: `28 b5 2f fd`）
- Python 的 import hook 在 import 时自动解压，但 `inspect.getsource()` 无法获取源码
- 必须用 `zst_透明层.zst_read()` 解压

**失败历程：**
1. PowerShell here-string → 中文+特殊字符解析失败
2. exec'd Python 代码中 `import zstandard as zstd` → 模块名不匹配（系统用 `zst_透明层`）
3. 直接 `from zst_透明层 import zst_read` → 成功

**最终方案：** Python 脚本遍历目录 → ZSTD 魔头检查 → `zst_read()` 解压 → `shutil.copy2()` 明文备份到 `_pre_merge_backup/`。

### 3.2 文件写入（4次失败→成功）

- write 工具参数格式错误（path 缺失）→ 改用 exec 写 Python 文件
- PowerShell 的 here-string `@"..."@` 中中文/Python GOTO 语法冲突 → 改用 Python 脚本写文件
- `知识蒸馏器.__init__()` 缺少 `向量寄存器` 参数 → 改为 `try: self.蒸馏器 = 知识蒸馏器(None)`
- `知识图谱.__init__()` 同样问题 → 同级修复

### 3.3 关键 Bug 修复

**蒸-馏过滤不生效：** `/feed` HTTP handler 硬编码返回 `{'ok': True, '已学习': True}`，完全忽略了 `守护.投喂()` 的返回值。蒸馏过滤逻辑本身是正确的，只是没把结果吐出来。

**修复前：**
```python
守护.投喂(text, source)
return self._json({'ok': True, '已学习': True})  # 永远返回已学习
```

**修复后：**
```python
result = 守护.投喂(text, source)
return self._json({'ok': True, **result})  # 返回真实结果
```

**状态统计字段也错了：** `getattr(守护, '总条数', 0)` → v2 用 `总计数` 不是 `总条数`。

## 七、关键教训

1. **ZSTD 透明层解码：** 不能用 `inspect.getsource()` 获取 ZSTD 压缩模块的源码，必须用 `zst_read()`。写脚本时先在命令行测试一行确认能用，再写完整脚本。
2. **HTTP handler 返回值过滤：** 不要硬编码返回值，必须把被调用函数的真实结果传回客户端。
3. **参数名一致性：** v1→v2 改名时检查所有引用（`总条数`→`总计数`），HTTP handler 和 Python 核心分开维护容易漏。
4. **备份多次失败不要硬扛：** 换方案（PowerShell → Python），找到真正的瓶颈（ZSTD 解码 → import hook 限制 → zst_read 直读）。
5. **豆包资料只参考不盲信：** 资料够快够广，但细节和本地适配要自己验证。
